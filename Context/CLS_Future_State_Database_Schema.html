CLS Future-State Database Schema

Approximate database design for a fully automated freight-forwarding operating system that replaces AMS and Gensoft, while using INTTRA as an external ocean-execution integration layer.

Designed for PostgreSQL Single source of truth INTTRA-ready CRM + Rates + Booking + SI + BL + Cut-offs + Documents

1. Design principles

One shipment record from start to finish

Create a shipment/job as soon as a confirmed booking or serious booking request exists. Do not wait until SI or BL stage.

AMS + Gensoft replaced by one database

Customer master, inquiry tracking, rates, quotation, booking, SI, BL, documents, approvals, and audit trail are stored in one platform.

INTTRA is an integration source

INTTRA can support booking, booking confirmation, schedules, rates, and visibility, but the internal platform remains the system of record.

Every document has versioning

SI, BL, release order, invoice, and supporting documents must have version history, approval status, and source traceability.

Every manual action has an audit trail

Changes to rates, quotations, bookings, SI, BL, cut-offs, approvals, and customer messages should be logged.

Cut-offs trigger workflows

SI cut-off, VGM cut-off, gate cut-off, CFS cut-off, and BL cut-off should create alerts and task reminders automatically.

Important: The provided INTTRA API reference covers booking, schedules, rates, and visibility. It does not show a dedicated API for SI submission, BL draft approval, House BL creation, Switch BL, or cut-off management. Therefore those areas are designed as internal system modules.

Core rule: shipments becomes the main parent table. Bookings, SI, BLs, containers, documents, cut-offs, tasks, approvals, and events all connect back to shipments.id.
House/Master BL rule: a shipment can have one or more Master BLs and one or more House BLs. They are linked through bl_relationships.
Cross-trade/Switch BL rule: separate BL versions are linked through switch_bl_chains so the system can protect confidential supplier/buyer information.

Booking confirmation webhookcarrier_booking_confirmations, release_orders, status_historyINTTRA confirmation updates booking status and can trigger release-order creation and customer notification.
Booking amendment / cancellationbooking_amendments, carrier_booking_requests, status_historyAmend/cancel action is first recorded internally, then pushed to INTTRA. Response is stored for audit.
Ocean schedule searchschedule_searches, schedule_options, vessels, voyagesINTTRA schedule data can prefill vessel/voyage/ETD/ETA options, but cut-offs still need internal validation.
Contract and spot rate searchrate_searches, rate_offers, rate_chargesINTTRA rate results are stored as rate offers. Sales markup and quotation are handled internally.
Visibility / track-and-tracetracking_events, container_events, shipment_exceptionsTrack events are pulled/stored, then internal rules decide whether to alert CS, Procurement, customer, or agent.

6. Sample PostgreSQL DDL for the core design

This is not the full production DDL. It shows how the main tables would be structured.

CREATE TABLE organizations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  org_type TEXT NOT NULL, -- customer, carrier, agent, supplier, consignee, notify_party
  registration_no TEXT,
  tax_no TEXT,
  risk_rating TEXT,
  status TEXT NOT NULL DEFAULT 'active',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE contacts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID REFERENCES organizations(id),
  name TEXT NOT NULL,
  email TEXT,
  phone TEXT,
  whatsapp_no TEXT,
  role_title TEXT,
  is_primary BOOLEAN DEFAULT false
);

CREATE TABLE inquiries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  customer_id UUID REFERENCES organizations(id),
  inquiry_channel TEXT NOT NULL, -- email, whatsapp, phone, web_form
  inquiry_status TEXT NOT NULL DEFAULT 'new',
  origin_port_id UUID,
  destination_port_id UUID,
  commodity TEXT,
  expected_loading_date DATE,
  owner_id UUID,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE rate_offers (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  source TEXT NOT NULL, -- INTTRA, carrier_portal, email, procurement_manual
  carrier_id UUID REFERENCES organizations(id),
  origin_port_id UUID,
  destination_port_id UUID,
  rate_type TEXT NOT NULL, -- contract, monthly, spot
  contract_no TEXT,
  valid_from DATE,
  valid_to DATE,
  currency CHAR(3),
  total_amount NUMERIC(14,2),
  raw_source_json JSONB,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE quotations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  inquiry_id UUID REFERENCES inquiries(id),
  customer_id UUID REFERENCES organizations(id),
  quote_no TEXT UNIQUE NOT NULL,
  status TEXT NOT NULL DEFAULT 'draft',
  valid_until DATE,
  created_by UUID,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE shipments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shipment_no TEXT UNIQUE NOT NULL,
  customer_id UUID REFERENCES organizations(id),
  quotation_id UUID REFERENCES quotations(id),
  shipment_type TEXT NOT NULL, -- export, import, cross_trade
  trade_type TEXT, -- direct_bl, house_master, switch_bl
  mode TEXT NOT NULL DEFAULT 'ocean',
  status TEXT NOT NULL DEFAULT 'created',
  owner_id UUID,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE carrier_booking_requests (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shipment_id UUID NOT NULL REFERENCES shipments(id),
  carrier_id UUID REFERENCES organizations(id),
  booking_no TEXT,
  inttra_reference_id TEXT,
  inttra_reference_no TEXT,
  booking_status TEXT NOT NULL DEFAULT 'draft',
  submitted_via TEXT, -- INTTRA, liner_portal, email, phone
  submitted_at TIMESTAMPTZ,
  raw_request_json JSONB,
  raw_response_json JSONB
);

CREATE TABLE shipping_instructions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shipment_id UUID NOT NULL REFERENCES shipments(id),
  si_no TEXT,
  version_no INT NOT NULL DEFAULT 1,
  source_format TEXT, -- web_form, excel, word, pdf, email
  status TEXT NOT NULL DEFAULT 'draft',
  received_at TIMESTAMPTZ,
  approved_at TIMESTAMPTZ,
  raw_source_document_id UUID
);

CREATE TABLE bills_of_lading (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shipment_id UUID NOT NULL REFERENCES shipments(id),
  bl_no TEXT,
  bl_type TEXT NOT NULL, -- master, house, direct, switch_first_leg, switch_second_leg
  version_no INT NOT NULL DEFAULT 1,
  status TEXT NOT NULL DEFAULT 'draft', -- draft, customer_approved, final, amended, cancelled
  source_system TEXT, -- internal, liner_portal, INTTRA_future, manual
  issue_place TEXT,
  issue_date DATE,
  document_id UUID,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE bl_relationships (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  parent_bl_id UUID NOT NULL REFERENCES bills_of_lading(id),
  child_bl_id UUID NOT NULL REFERENCES bills_of_lading(id),
  relation_type TEXT NOT NULL -- master_to_house, original_to_amended, switch_first_to_second
);

CREATE TABLE cutoff_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shipment_id UUID REFERENCES shipments(id),
  booking_id UUID REFERENCES carrier_booking_requests(id),
  cutoff_type TEXT NOT NULL, -- SI, BL, VGM, CY_GATE, CFS, ENS, EAD
  cutoff_at TIMESTAMPTZ NOT NULL,
  timezone TEXT,
  source TEXT, -- carrier_email, terminal_notice, manual, API
  status TEXT NOT NULL DEFAULT 'open'
);

CREATE TABLE documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  document_type TEXT NOT NULL,
  file_name TEXT NOT NULL,
  storage_url TEXT NOT NULL,
  checksum TEXT,
  version_no INT DEFAULT 1,
  uploaded_by UUID,
  uploaded_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE integration_messages (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  partner_name TEXT NOT NULL, -- INTTRA, MSC, CMA, OOCL, email_parser
  entity_type TEXT NOT NULL,
  entity_id UUID NOT NULL,
  direction TEXT NOT NULL, -- outbound, inbound
  endpoint TEXT,
  request_json JSONB,
  response_json JSONB,
  status TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE tracking_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shipment_id UUID REFERENCES shipments(id),
  container_id UUID,
  source TEXT NOT NULL, -- INTTRA, carrier_portal, manual
  event_code TEXT,
  event_name TEXT NOT NULL,
  event_time TIMESTAMPTZ,
  location_text TEXT,
  raw_event_json JSONB,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

8. Implementation recommendation

Best approach: Build the platform around shipments as the central operational record, connect all modules to it, and integrate INTTRA through an integration layer. Do not let INTTRA become the master database because it does not cover the full internal CLS process.

Recommended build phases:

  1. Phase 1: Customer master, inquiry tracking, rates, quotations, and shipment/job creation.
  2. Phase 2: Booking workflow, INTTRA booking integration, release orders, and cut-off reminders.
  3. Phase 3: SI web form, BL versioning, House/Master BL links, approvals, and document checklist.
  4. Phase 4: Track-and-trace, exception workflows, destination agent notifications, and dashboards.
  5. Phase 5: Finance-lite/costing/invoice integration if the operating system must fully replace Gensoft billing workflows.

Prepared from the provided AS-IS process mapping and INTTRA Ocean Execution API reference. This is an approximate logical schema for solution design and should be validated with operations, finance, documentation, and technical teams before implementation.
