INTTRA Ocean Execution
API Reference

A consolidated reference for INTTRA by e2open's RESTful Ocean Execution APIs — covering Booking, Ocean Schedules, Rates, and Visibility (Track & Trace). All endpoints, headers, parameters, and example requests in one place.

Source: apidocs.inttra.com Version: v1 Protocol: HTTPS · JSON Endpoints: 18

00Conventions

All INTTRA APIs follow a common request/response style. Knowing the conventions once saves repeating them per endpoint.

  • • RESTful, accessible over HTTPS using application/json in both directions.
  • • API version targeted via Accept header (current is v1).
  • • All consumer-API calls require a Bearer token in the Authorization header.
  • • An expired token returns HTTP 401 — request a new one from /auth.
  • • Tokens default to a fixed timeout (token_ttl: 600 seconds in the sample).

01Authentication

Before calling any consumer API the customer system must retrieve an authentication token by calling the Authentication API with the credentials provisioned by INTTRA.

AUTHGet access token
GET {BASE_URL}/auth

Exchanges client credentials for a short-lived Bearer access token to be presented on subsequent calls.

Headers
KeyRequiredValue / Description
client_idrequiredClient identifier issued during provisioning.
client_secretrequiredClient secret issued during provisioning.
grant_typerequiredclient_credentials
cache-controloptionalno-cache (recommended)
User-AgentoptionalCaller's user-agent string.
Example Request
curl --request GET \
  --url '{BASE_URL}/auth' \
  --header 'cache-control: no-cache' \
  --header 'client_id: ${CLIENT_ID}' \
  --header 'client_secret: ${CLIENT_SECRET}' \
  --header 'grant_type: client_credentials'
Example Response
{
  "tokenGeneratedUtc": "2017-11-07 15:03:11",
  "tokenLastAccessUtc": "2017-11-07 15:03:11",
  "client_id": "${CLIENT_ID}",
  "access_token": "token_uuid",
  "token_type": "Bearer",
  "grant_type": "client_credentials",
  "token_expiry_type": "FixedTimeout",
  "token_ttl": 600,
  "scope": "OCEANSCHEDULE_USER"
}
Token reuse: The token should be reused across calls until it expires. On 401, request a new token from this endpoint.

Submission, retrieval, amendment & cancellation of ocean-freight bookings.

#01Confirmation-Webhook
POST https://api-yourcompanyurl.com/booking/webhook

Booking → Booking Confirmation Webhook

The URL is customer's company provided URL which will be registered with INTTRA as a Webhook Subscription. for e.g. http://api-booking-company.com/booking/webhook For Authentication purpose, the Subscription can register company provided secret key which will then be sent in the POST request as an Authorization Header. The payload for the request will be the Booking Confirmation in JSON format. An example booking confirmation payload can be viewed in this API documentation request.

  --header 'Authorization: Bearer <access_token>'

Notes: Search can be performed using only one parameter at a time. Search by Equipment Reference gets all milestone events associated with the equiment. Only events related to the shipment of the last event processed will be returned. Search by Carrier Booking Reference gets all milestone events associated with all equipments associated with the booking identified by the requested carrier booking reference.
